# Matching engine benchmark: 10M synthetic commands

Run date: 2026-11-09 (Asia/Singapore)  
Code revision under test: `5cb9fa3`  
Command: `equity-matching-engine benchmark --events 10000000 --seed 20261109 --trials 5 --warmup-events 100000`

## Environment

- CPU: AMD Ryzen 9 9900X, 12 cores / 24 logical processors
- OS: Windows 10 Pro 25H2, build 26200
- Rust: `rustc 1.99.1 (58cf8f9c3 2026-10-13)`, target `x86_64-pc-windows-msvc`
- Build: Cargo release profile, thin LTO, one codegen unit
- Process affinity: pinned to logical processor 0 (Windows affinity mask `1`)
- Warm-up: 100,000 commands using seed `18446744073689290506`
- Measured trials: five, each with the same pre-generated seed `20261109`

## Workload and measurement boundary

Each trial pre-generates 10,000,000 valid engine commands before timing: 7,507,060 submits and 2,492,940 cancels. Orders use integer prices around 10,000 ticks, quantities from 1 to 100 lots, and both sides can cross. Each trial generated 4,963,042 trades totaling 131,420,471 lots. Identical final state fingerprints across trials show deterministic final state for this workload.

Elapsed throughput covers the command-processing loop and its per-command clock reads. Service latency is sampled around each matching-engine submit or cancel call, also including those clock reads. This is an isolated single-threaded matcher measurement. It excludes workload generation, external feed ingestion, network I/O, queue waiting, and persistence. The run was not an open-loop queue/backpressure test. The process was pinned to one logical processor, but the test does not measure CPU counters or system-wide contention.

## Result

Median throughput was **6,680,627.84 commands/s** across the five trials, with a range of 6,552,566.82 to 6,758,856.57 commands/s. Each run measured p50 service latency of 100 ns, p95 of 300 ns, and p99 of 400 ns. The observed maximum per-command sample ranged from 69.176 ms to 70.583 ms, indicating rare large scheduling or system stalls that the p99 does not capture.

This run supports the matching-only claim of at least 5M synthetic mixed commands/s at under 1 microsecond p99 on one pinned logical processor for this specific workload and measurement method. It does not support claims about IBKR capture/replay, paper backtesting, bounded queues, or zero-loss queued pipeline capacity.
